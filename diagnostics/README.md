# 문제시 진단

결과가 기대와 다를 때 **원인을 한 요소씩 좁히는** 조건 비교 실험을 둔다.
일반 실행(`notebooks/`)과 분리하는 이유는 진단이 느리고(AF2 여러 회), 실패해도 끝까지
돌려야 하며, 출력으로 지표가 아니라 입력 배열까지 저장해야 하기 때문이다.

## 설계 원칙

- 기준 조건 하나를 정하고 **한 번에 한 항목만** 바꾼다.
- 각 조건은 별도 프로세스에서 실행한다. 하나가 실패해도 나머지를 계속 진행한다.
- 같은 조건을 두 번 넣어 재현성을 확인한다 (`*_repeat`).
- 정답 좌표를 쓰는 조건은 **대조군으로 명시**하고, 입력이 다르다는 점을 표에 함께 적는다.
- 지표만 저장하지 않는다. 원시 특징·전처리 특징·초기 좌표·모델 설정·신뢰도 배열을 모두
  저장하고 기준 조건과 배열 단위로 비교한다 (`feature_differences.json`).

마지막 항목이 결정적이었다. "무엇이 달랐나"를 추측하지 않고 배열 차이로 확인할 수 있었다.

읽는 법:

- 위 9개 조건은 모두 설계 좌표에서 출발하고 모두 실패한다. 탐색 설정(시드·recycle·정밀도)과
  입력 준비 방식을 바꿔도 실패 범위를 벗어나지 못한다.
- 같은 시드에서 32.780 Å이 그대로 재현되므로 비결정성이나 수치 정밀도 문제가 아니다.
- 마지막 두 조건만 통과한다. 두 조건의 공통점은 **표적 좌표를 실제 구조에서 가져온 것**이다.
- `published_target_control`은 결합체는 설계 좌표를 그대로 쓰고 표적 원자만 교체한 조건이다.
  이것이 통과하므로 결합체 설계가 아니라 표적 입력이 원인임이 분리된다.

## 수정안의 판정 결과

`grafted_target_sidechains`가 수정안이다. 실험 구조(1WWW 체인 X, 서열 동일)에서
사이드체인을 잔기별로 이식한다. 설계 주사슬은 편차 0.000000 Å로 보존되고 표적
사이드체인 중원자 378개가 채워진다.

**통과했다.** 1.496 Å / PAE 5.86으로, 정답 좌표를 투입한 대조군(1.654 Å / 4.86)과
같은 영역에 들어갔다. 공개 AF2 구조와의 차이는 0.191 Å로 대조군(0.409·0.412 Å)보다
오히려 작다. 대조군은 AF2 자신의 예측을 되먹인 것이고, 이쪽은 독립적인 결정 구조를 썼다.

## 이 조건이 추가로 가려낸 것

입력 특징 배열을 실패 기준(`original_thread`)과 비교하면, 이식 조건은
`template_pseudo_beta`(CB 위치) 최대 차이가 **0.202 Å**에 불과하다.
`published_target_control`은 같은 값이 1.425 Å였다.

즉 설계 주사슬이 그대로이고 CB도 사실상 제자리인데, **CB 바깥 사이드체인 원자만 바뀌어
32.780 Å이 1.496 Å이 됐다.** 이전 대조군은 주사슬과 CB를 함께 움직였기 때문에 원인을
사이드체인으로 좁힐 수 없었다. 이 조건이 그것을 확정했다.
[문제 기록](../docs/issues/2026-11-18-trka-target-sidechains.md)
