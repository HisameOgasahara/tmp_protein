# GFP 결합 자세 재현: 원인 분석과 개선 방향

2026-11-17 · 기준 실행 v0.1.4 · 실행 커밋 `43c0d45`

가장 강한 실패 근거는 알려진 결합체 두 개의 결합 자세를 여섯 번의 예측에서 한 번도 회복하지 못했다는 점이다. GFP 구조 보존은 개선됐지만, 결합체의 상대 위치를 평가할 조건은 아직 확보되지 않았다.

| 단계 | 관찰 결과 | 우선 조치 |
| --- | --- | --- |
| 대조군 입력 | 두 대조군에 3G9A GFP 템플릿 사용, 결합체는 서열만 제공 | 각 대조군의 결정 구조에서 개별 체인 구조 제공 |
| RF3 예측 | 접촉면 회복 0/6 | 체인 간 정답 거리를 가리고 구조 조건과 recycle 수 비교 |
| 자세 평가 | GFP 접촉 잔기 집합의 Jaccard와 GFP RMSD 사용 | GFP 정렬 후 결합체 RMSD와 잔기 쌍 접촉 회복률 추가 |
| 후보 생성 | 뼈대 2개 × 서열 2개, 생성 시드 고정 | 대조군 평가 조건 확보 후 탐색 규모 검토 |
| 형광 회귀 | 기본 데이터 2그룹, 최소 요구 3그룹 | 독립 실험 데이터 확보 후 별도 평가 |

## [A2] 대조군 입력과 정답 정보 분리

- Enhancer는 3K1K의 GFP A 체인과 결합체 C 체인, minimizer는 3G9A의 GFP A 체인과 결합체 B 체인을 사용한다.
- 관측된 잔기를 각 전체 서열에 대응시킨다. GFP 발색단의 `X → SYG` 처리는 기존 입력과 동일하게 유지한다. 성숙 발색단의 화학 구조를 복원하는 실험은 별도 과제다.
- 각 체인의 좌표를 독립적으로 회전·이동해 원래 결합 위치를 제거한다. 참조 복합체 좌표는 자세 평가에만 사용한다.
- RF3 템플릿의 분자 간 거리 제공 확률을 0으로 지정하고, 실제 입력 특징의 체인 간 조건 마스크가 비어 있는지 확인한다. 좌표 이동만으로 정답 정보 차단을 보장하지 않는다.
- 두 체인 템플릿을 사용한 결과는 결합 상태에서 추출한 개별 구조를 이용한 재도킹 결과다. 서열만으로 새 결합체를 예측하는 성능과 구분한다.

고정 버전의 [템플릿 구현](https://github.com/RosettaCommons/foundry/blob/0d0b0ba44fab7ca76aa4b625c014ce5964c7d284/models/rf3/src/rf3/data/ground_truth_template.py)은 `molecule_id`가 다른 토큰 쌍의 거리 조건을 가릴 수 있다. [입력 파이프라인](https://github.com/RosettaCommons/foundry/blob/0d0b0ba44fab7ca76aa4b625c014ce5964c7d284/models/rf3/src/rf3/data/pipelines.py)과 최종 특징 마스크를 함께 확인한다.

## [A3] 비교 순서와 계산 설정

| 실행 | GFP 템플릿 | 결합체 템플릿 | Recycles | Seeds | 목적 |
| --- | --- | --- | --- | --- | --- |
| 기준 | 각 대조군의 GFP | 없음 | 3 | 0, 1, 2 | 입력 구조를 통일한 비교 기준 |
| 반복 증가 | 각 대조군의 GFP | 없음 | 10 | 0, 1, 2 | recycle 수 효과 분리 |
| 개별 구조 제공 | 각 대조군의 GFP | 해당 결정 구조 | 10 | 0, 1, 2 | 결합체 접힘과 결합 위치 탐색 분리 |
| 탐색 확대 | 개선된 조건 | 개선된 조건 | 10 | 0–9 | 드문 성공 자세와 순위 문제 확인 |

모든 실행에서 `num_steps=50`, `diffusion_batch_size=1`을 유지한다. 기본 실행은 개별 구조 제공 조건으로 두고, 앞선 두 조건은 설정을 바꿔 비교한다. 탐색 확대는 앞선 결과에서 개선이 관찰된 뒤 실행한다.

[RF3 공식 설정](https://github.com/RosettaCommons/foundry/blob/0d0b0ba44fab7ca76aa4b625c014ce5964c7d284/models/rf3/README.md#command-line-arguments)은 기본 recycle 수를 10으로 안내하며, 50 diffusion steps에서 성능 저하를 관찰하지 않았다고 설명한다. 따라서 steps 증가의 우선순위는 낮다. MSA 추가는 개별 구조 제공 실험 이후 서열 입력 조건에서 비교할 수 있다.

## [A4] 자세 평가와 후속 판단

| 지표 | 계산 기준 | 해석 |
| --- | --- | --- |
| GFP Cα RMSD | 관측 잔기로 기준 GFP에 정렬 | 표적 구조 보존 |
| 결합체 Cα RMSD | GFP 정렬 변환을 결합체에 그대로 적용 | 상대 위치와 방향 오차 |
| GFP 접촉면 Jaccard | 기준·예측 GFP 접촉 잔기 집합 비교, Cα 8 Å | 결합 부위 겹침 |
| 잔기 쌍 접촉 회복률 | 기준 GFP–결합체 접촉 쌍 중 예측에서도 Cα 8 Å 이내인 비율 | 접촉 상대의 재현 |
| 충돌·ipTM 순위 | 전체 시드 결과에 함께 기록 | 충돌과 점수화 실패 분리 |

기존 회복 기준인 GFP RMSD ≤ 3 Å, Jaccard ≥ 0.5, 충돌 없음을 비교용으로 유지한다. 새 두 지표는 별도 수치로 보고하며, 기존 기준 통과만으로 정확한 방향까지 재현했다고 판정하지 않는다. 결합체를 따로 정렬한 RMSD는 접힘 평가에만 사용한다.

- 개별 구조 제공 조건에서도 자세 오차가 크면, 분리한 동일 구조를 사용하는 단백질–단백질 도킹과 비교한다.
- 개별 구조 제공 조건에서만 개선되면, 결합체 서열 입력의 접힘과 구조 정보 부족을 우선 조사한다.
- 정확한 자세가 생성되지만 ipTM 상위에 오르지 않으면, 샘플 생성과 점수화 문제를 분리해 다룬다.
- 두 대조군에서 자세 재현 조건을 확보한 뒤 기존 후보의 생성 구조를 개별 템플릿으로 사용하는 평가로 확장한다.

## [A5] 구현 및 실행 상태

과거 실행 01–03의 원본 ZIP, 설정, 구조, 지표, 로그는 저장소의 [results](../results)에 보존한다. 새 조건의 GPU 예측 결과는 아직 없으며, 개선 효과는 다음 Colab 실행에서 판정한다.

v0.1.5의 Colab에서 `BENCHMARK_TEMPLATE`은 `target` 또는 `both`, `BENCHMARK_RECYCLES`는 3 또는 10, `BENCHMARK_SEEDS`는 쉼표로 구분한 시드 목록으로 지정한다. 실행 조건은 `config/source.json`, 각 결정 구조의 서열 대응과 좌표는 `config/reference_*.json`에 저장한다. 개별 결과는 `metrics/benchmark_poses.csv`, 요약은 `metrics/benchmark_summary.json`에서 확인한다.

입력과 자세 계산은 [benchmark.py](../gfp_pipeline/benchmark.py), RF3 실행과 결과 집계는 [stages.py](../gfp_pipeline/stages.py), 실행 설정은 [run.py](../gfp_pipeline/run.py)에서 처리한다. 전체 설계 모드는 기존 GFP 템플릿·recycle 3 설정을 유지한다.

로컬 확인에서는 두 결정 구조의 서열 대응, 정답 자세와 전체 강체 변환의 RMSD, 결합체 이동·회전 오류 검출, 개별 템플릿의 내부 거리 보존, 요약 집계가 통과했다. 합성 특징 마스크로 체인 간 거리 유출과 템플릿 누락을 거부하는 검사도 통과했다. RF3 전체 전처리와 GPU 추론의 연결은 Colab에서 확인해야 한다.
